# 회원·회사 관리 운영 통합 — 2026-10-19

## 적용 범위

회원 개발 브랜치 feature/member-auth-admin을 최신 운영 main과 통합한다. 공개 홈페이지의 자료실 검색·상담 검증·한국어 설정·이미지 개선을 유지하고, 공통 메뉴를 로그인 상태에 따라 전환한다.

- 회원가입, 이메일 확인 안내, 승인된 회원 로그인·로그아웃
- 내 회사 목록, 회사별 권한·등기사항·비공개 문서 조회
- 관리자 회원 승인, 회원-회사 연결, 직원 권한·회사 배정
- 회사 선등록, 임원·기간·특별관리·연락처·업무로그, Excel 관리
- 관리자 MFA, 비밀번호 변경, 계정·탈퇴 요청
- 기존 견적서 화면 포함. 견적 결과 생성은 별도 처리기/Edge Function 구성에 의존하며 이번 배포 검증 범위에서 제외한다.

## 통합 보완

1. 공개 메뉴와 회원 메뉴를 하나의 SiteHeader로 연결. 업무분야·자료실·상담·오시는 길과 모바일 회원가입 경로를 유지한다.
2. 관리자/회원 영역 진입 전에 서버의 회원 프로필로 승인 상태와 역할을 확인한다. 초기 비밀번호 변경과 관리자 MFA를 해당 화면으로 안내한다. 권한 확인 실패 시 오류와 재시도 버튼을 표시한다.
3. 실제 데이터 권한은 DB RLS에서 별도로 검사한다. 화면의 로그인 상태만으로 회사자료를 허용하지 않는다.
4. 손상된 저장 세션은 폐기하고, 로그아웃 뒤 늦게 끝난 갱신 요청이 세션을 복원하지 못하도록 수정한다.
5. 내부 화면의 검색 색인을 차단하고 환경변수 예시를 실제 코드의 publishable key 이름과 맞춘다.

## 배포 전 검증

- npm run build: 성공. TypeScript 검사 및 32개 정적 경로 생성 포함.
- node --test tests/contact.test.mjs tests/member-session.test.mjs: 41개 통과.
- tests/member-access.sql: 운영 DB의 실제 RLS를 anon/authenticated 역할로 검증하는 19개 assertion 통과.
- DB 검증은 합성 회원/회사/문서 메타데이터를 생성하고 내부 subtransaction에서 모두 rollback한다. 기존 운영 계정으로 로그인하거나 비밀번호를 변경하지 않는다.
- 승인 고객은 연결된 회사·임원·문서 메타데이터만 조회한다. 미승인/정지 회원은 조회하지 못한다. 일반 고객의 회사 수정 및 관리자 RPC 호출은 차단된다.
- 직원은 배정된 회사만 조회하고, 허용된 특별관리 자료만 수정한다. 회사명·법인등록번호 변경은 관리자 권한이다.
- 회사 440개, 임원 695건 및 공개 회사 수 440개 확인. 기존 자료를 운영 배포 때문에 재등록하지 않는다.

## 운영 설정

Vercel 프로젝트 soop-law-homepage의 production/preview에 다음 공개 환경변수가 구성되어 있는지 확인한다.

- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY

RESEND_API_KEY는 상담 전달 전용 서버 변수다. service_role 키는 브라우저 코드에 사용하지 않는다.

실제 사용자 비밀번호와 인증 앱으로의 로그인, 신규 가입 이메일 수신, 실제 문서 업로드/다운로드·견적서 생성은 테스트 계정 및 외부 서비스 조건에 따라 별도 확인이 필요하다. 기존 계정의 비밀번호·이메일·MFA 설정을 배포 과정에서 변경하지 않는다.
