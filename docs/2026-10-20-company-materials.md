# 임원 임기·사무소 자료 보관현황·자료 요청

## 변경된 운영 방식

회사 상세 화면에서 임원 임기, 정관·주주명부의 사무소 보관 여부를 확인한다. 회사 파일은 업로드·다운로드하지 않는다. 기존 문서 관리 주소도 보관현황 화면으로 전환한다.

- 보관상태: 확인 필요 / 사무소 보관 중 / 사무소 미보관. 확인한 회사만 상태를 입력하고 확인일을 남긴다. 과거 업로드만으로 보관 여부를 추정하지 않는다.
- 승인된 고객은 연결된 회사의 임기와 보관현황을 조회한다. 자료 요청은 활성 회사 연결, 회사 조회·자료 요청 권한, 소유주 또는 관리권한 지위를 모두 요구한다. 하위 멤버에게는 요청을 허용하지 않는다.
- 관리자와 자료관리 권한이 있는 담당 직원은 보관상태를 수정한다. 직원은 전역 권한과 회사 배정 권한이 모두 필요하다.
- 요청자료를 선택하고 회신 주소를 입력하면 `soop@sooplaw.com`으로 요청 메일이 전달된다. 발신 주소도 `soop@sooplaw.com`이며 Reply-To는 요청자가 기재한 주소다. 첨부파일이나 자동 자료 회신은 없다.
- 회신 주소는 인증된 주소가 아니다. 사무소에서 요청 권한·제공할 자료·수신 주소를 확인하고 별도로 회신한다.
- 요청번호로 재시도 내용을 고정하고 메일 제공자의 멱등키를 사용한다. 한 계정의 신규 요청은 10분에 5건으로 제한한다. 직접 REST 등록도 같은 제한을 받는다. 최초 접수 후 23시간을 넘긴 메일 재시도는 새 요청을 요구한다.
- 요청기록 생성과 메일 제공자의 접수는 구분한다. 제공자 실패 시 성공으로 안내하지 않으며 같은 요청번호로 재시도한다. 실제 메일 도착·열람은 별도 확인이 필요하다.

## DB 반영

`20261020064431_company_material_holdings_requests.sql`은 운영 DB에 적용했다.

- `company_material_holdings`, `company_material_requests` 테이블에 RLS와 필요한 최소 권한을 적용했다.
- `storage.objects`에 회사 문서 보관함을 제외하는 RESTRICTIVE 정책을 추가하여 기존 허용 정책이 있어도 anon/authenticated 계정의 파일 접근·업로드를 차단했다. 홈페이지 관리자도 이 제한을 받는다. 서비스 관리 권한은 별개다.
- 기존 `company_documents` 메타데이터도 홈페이지 역할에서 접근·신규 등록하지 못하게 했다.
- 과거 등기부 업로드 권한을 해제하고 트리거로 재활성화를 차단했다. 기존 권한관리 RPC의 인자는 호환성을 위해 유지한다.
- 회사 440개, 임원 695건을 유지했다. 기존 회사 문서 파일 1개를 삭제하지 않았다. 기존 파일을 온라인 보관 자체에서 완전히 제거하려면 별도 보관·삭제 결정을 해야 한다. 과거 발급된 서명 URL이 있다면 별도 만료·폐기 검토가 필요하다.

## 검증

- 자동 테스트 68개 통과: 인증·권한, 잘못된 회사 요청, 입력 검증, 이메일 헤더 주입, 고정 수신자, 첨부 없음, 전송 실패·중복 재시도 포함.
- 신규 DB 검증: 다른 회사 요청 차단, 하위 멤버·미승인·권한 회수 계정 차단, 직원 담당회사 제한, 보관현황 수정 제한, 직접 등록 우회 차단, 요청 횟수 제한, 관리자 파일 접근·업로드 차단. 합성 자료는 모두 롤백했다.
- 기존 DB 권한 검증 19개 통과. 은퇴한 문서 조회는 0건을 기대하도록 변경했다.
- 새 기능 TSX/API의 ESLint와 production build/TypeScript 검사 통과.
- 실제 고객 자료 요청이나 실제 메일 발송은 하지 않았다. 브라우저 시각 검사와 실제 메일 수신은 별도 확인이 남아 있다.
- 기존 보안 점검 경고(권한 함수 15개, 유출 비밀번호 차단 비활성)는 추가되지 않았다. 이번 변경이 계정탈취·기존 DB 정보 유출 위험까지 제거한다는 의미는 아니다.
