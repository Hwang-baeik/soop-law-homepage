6. 홈페이지 본문을 서버 컴포넌트로 전환하고 상담 입력만 클라이언트 컴포넌트로 분리. 첫 화면이 JavaScript 애니메이션의 초기 투명도에 의존하지 않도록 수정.

8. 부동산·상속등기 상담 카드 및 전화/이메일 직접 연결 추가.
9. 공유 입력 검증으로 클라이언트와 서버의 기준 통일. 공백, 자료형, 이메일, 제목 줄바꿈, 분류, 동의 여부, 입력 길이 검사. JSON 파싱 오류를 400, 지원하지 않는 형식을 415, 32KB 초과 요청을 413으로 응답.
10. 상담 실패 시 작성 내용 보존 및 서버 오류 안내 표시. 발송 중 입력 잠금. 서비스 설정 미비 시 내부 환경변수명 대신 대체 연락처 안내.
11. 개인정보 처리항목 설명을 현재 상담 입력항목과 일치하도록 정리. 새로운 보유기간이나 업무처리 사실을 임의로 추가하지 않음.
12. 사이트맵에서 문서가 아닌 #fragment 주소를 제거하고 자료실과 실제 글 주소를 포함. 자료실과 상세 글의 canonical, 자료실 공유 메타정보 보완.

## 확인 한계와 후속 과제

### 회원 시스템 (운영 병합 전 필수)

- Supabase 프로젝트 soop-law-homepage (fsoywupylioyzxftdlgm)는 프로젝트 목록상 INACTIVE로 표시됨.
- 읽기 전용 연결 시험 `select now()`가 연결 시간 초과로 실패. 인스턴스 가동상태를 확인하고 복구한 뒤 검증 필요.
- Security Advisor는 lints=[]를 반환했으나 위 연결 실패가 있으므로 실제 접근권한 정상 또는 보안 검증 완료를 뜻하지 않음.
- 클라이언트의 로그인 화면 분기/세션 존재 여부는 DB의 RLS를 대체하지 않음. 실제 DB에 적용된 정책을 기준으로 확인해야 함.
- 관리자, 직원, 승인 고객, 미승인 고객, 회사 미연결 회원 계정으로 교차 회사 조회/수정/문서 다운로드 차단을 검증할 필요가 있음.
- 이메일 확인, 승인 후 로그인, 세션 갱신, MFA, 비밀번호 재설정, 탈퇴 후 기존 토큰, 문서 업로드/교체, 엑셀 왕복, 임기 알림 수신을 실제 환경에서 확인할 필요가 있음.
- 기존 회원 개발본은 임의로 운영 병합하거나 대체하지 않음. 공개 홈페이지 수정과 회원 개발본의 공통 헤더/상담 컴포넌트는 후속 병합 시 충돌 검토 필요.

### 공개 홈페이지

- 브라우저 화면 크기별 시각 확인과 실제 기기 키보드/스크린리더 사용 검사는 수행하지 못함. 관리형 실행 환경에서 요구하는 브라우저 제어 기능이 제공되지 않아 빌드 및 생성 HTML 검증으로 한정.
- Resend 실제 메일 수신은 테스트하지 않음. 운영 관리자 수신함에서 별도 수신 검증 필요.
- 전송 API에 분산 환경의 스팸/빈도 제한은 아직 없음. Vercel 방화벽 또는 영속 저장소 기반 제한을 설정할 때 배포 환경과 정상 상담 빈도를 함께 고려할 것.
- 개인정보 처리방침의 실제 메일 수탁/보관/파기 운영과 게시글의 현행 법령·판례 내용은 별도 실무 검토 대상. 이번 변경은 새 법률 해석을 추가하지 않음.
