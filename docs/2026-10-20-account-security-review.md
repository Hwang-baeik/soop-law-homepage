# 마이페이지 및 제한적 보안 점검 — 2026-10-20

## 변경

- 로그인한 회원에게만 상단 마이페이지 메뉴를 표시한다. 비로그인 로그인 화면의 비밀번호 변경 링크를 제거한다.
- 계정 설정 화면은 승인 상태를 확인한 뒤 표시한다. 비밀번호 변경 주소에 직접 접근한 비로그인 사용자는 양식을 표시하지 않고 로그인으로 이동한다.
- 본인의 이름·연락처만 수정한다. DB에서도 두 열에만 UPDATE 권한을 부여하며 다른 회원·역할·승인 상태 변경을 제한한다.
- 이메일 변경은 현재 비밀번호 재확인과 Auth 인증 절차를 사용한다. 비밀번호 재확인용 임시 로그인 세션만 종료하여 기존 MFA 세션을 유지한다.
- 비밀번호 변경 뒤 로그아웃한다. 최초 변경 완료 상태는 실제 Auth 비밀번호 변경 트리거로 기록한다.

## 검증 및 한계

- 자동 테스트 58개 통과. 개인정보 입력 검증 및 비밀번호 재확인 시 기존 세션 유지 검증 포함.
- 기존 DB 회사·임원·문서·직원 권한 검사 19개 통과. 추가로 본인 정보 수정, 다른 회원 수정 차단, 역할·승인 열 수정 차단 및 합성 데이터 원상복구를 검증했다.
- 변경 파일 ESLint, production build/TypeScript 검사를 실행한다. 실제 회원의 비밀번호·이메일 변경이나 고객 이메일 발송은 하지 않는다.
- 공개 스키마 테이블 16개 RLS 활성, 보관함 2개 비공개. 보관 중인 파일 1개가 있다. 익명 접근이나 다른 회사 파일에 대한 무제한 허용 정책은 이번 확인 범위에서 발견하지 않았다.
- 현재 계정의 MFA 등록은 없고, 유출 비밀번호 차단은 비활성이다. 관리자 MFA는 등록한 경우에만 추가 인증을 요구한다.
- 보안 점검 도구가 로그인 역할에서 호출 가능한 SECURITY DEFINER 함수 15개를 경고했다. 기능상 의도된 호출이 포함되므로 경고만으로 무단 유출 가능성을 확정할 수 없다. 권한 검사를 지속 검증해야 한다.
- 로그인 토큰은 sessionStorage에 보관하므로 XSS가 발생하면 탈취 위험이 있다. HttpOnly 쿠키 기반 서버 세션 및 엄격한 CSP는 별도 개선 과제다. 현재 CSP는 주로 프레임 삽입을 제한한다.
- 이 작업은 코드·설정·일부 권한 검증이며, 전문 침투시험이나 보안 무결성 보증이 아니다. 이메일 실제 수신 및 변경 완료 동작은 별도 확인이 필요하다.

## 권장 운영

임기관리에는 회사명·임원명·직위·기준일·임기·업무용 연락처 등 필요한 최소 정보만 사용한다. 신분증, 인감증명서, 주민등록번호 포함 원본, 금융·소송자료는 홈페이지에 올리지 않는 방안을 우선 권장한다. 파일을 올리지 않아도 기존 DB 정보와 계정 보호는 필요하다.

관리자 및 GitHub·Vercel·Supabase·이메일 계정에 2단계 인증과 서비스별 고유 비밀번호를 적용하고 직원에게 필요한 회사·기능만 부여한다. 중요 원본은 접근 제한된 사무소 저장소에 보관하고 암호화된 별도 백업 및 복구 점검을 운영한다. NAS의 인터넷 직접 노출은 피한다.

기존 파일 삭제·신규 업로드 중단·기존 데이터 축소는 사용자가 운영방식을 결정한 뒤 시행한다. 업로드 중단은 화면 버튼뿐 아니라 Storage/API 권한에도 적용해야 한다. 이번 배포에서는 파일 삭제나 업로드 권한 중단을 하지 않는다.
